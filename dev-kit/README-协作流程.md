# Muse（牛牛）+ WorkBuddy 开发调试协作流程

## 一句话分工
- **Muse = 大脑**：设计、写代码、找 bug 根因、写测试、记文档。不能直接碰你电脑上的文件。
- **WorkBuddy = 手**：在你 Windows 电脑上读文件、跑命令、改文件、复现问题、抓日志截图。
- **你 = 裁判 + 传话人**：目前他俩没有直连，你把文件 / 日志在中间转一次，或者用 Git / 云盘文件夹当中间站。

## 推荐的中间站（按好用程度排）
1. **Git 仓库（最推荐）**：GitHub / Gitee 建一个私有仓，项目放里面。Muse 给补丁（.diff / 新版文件），WorkBuddy 在本地 `git apply` / 覆盖文件、跑测试、`git commit`，结果写进 DEBUG_LOG.md 再提交。你发我最新的 commit / diff，我接着改。
2. **云盘同步文件夹**：OneDrive / 腾讯微云 / 百度网盘同步盘，固定一个文件夹 `D:\Dev-Share\`，两边都认这个路径。Muse 的文件你下载进这个文件夹，WorkBuddy 直接读。
3. **手动转接（零搭建）**：直接复制粘贴代码和报错。适合一次性的小修，不适合长期项目。

> 注意：不要让 WorkBuddy 直接改你没备份的东西。每次大改前先 `git commit` 或复制一份备份。

## 标准一轮循环（每次修 bug 都走这一圈）
1. **你给 WorkBuddy**：把《给WorkBuddy的指令.md》里的复现指令发给它，让它抓项目结构 + 完整报错，写进 `DEBUG_LOG.md`。
2. **你把 DEBUG_LOG.md 发给我**：贴全文或发文件，我分析根因，给出修复方案 + 补丁文件 / 新版代码。
3. **你把我的补丁交给 WorkBuddy**：让它按《给WorkBuddy的指令.md》里的“应用补丁”步骤覆盖 / 打补丁，备份旧文件。
4. **WorkBuddy 本地验证**：跑起来、跑测试、截图 / 贴运行结果，更新 `DEBUG_LOG.md`：通过 / 没通过。
5. **你把验证结果发给我**：通过了我就记下来、更新文档；没通过我再给下一版补丁，回到第 2 步。

一次只改一个问题，一次只验证一个补丁，别同时堆三四个改动，否则不知道是哪个修好的。

## 每次交接必须带的信息（缺了就没法调）
- 项目名、语言和版本：比如 Python 3.12 / tkinter，PikPakRetriever.py
- 出问题的操作步骤：点了什么、输入了什么关键词
- 完整报错：不要只截图半行，要全文 + 最后一行
- 相关文件和行号：比如 `PikPakRetriever.py 第 210 行`
- 最近改了什么：上次能跑是什么时候，改了哪几行

## 安全边界
- WorkBuddy 只改 TASK.md 里列出的文件，不碰系统文件、密码、账号文件。
- 密钥、API Key、账号密码不要写进 TASK.md / DEBUG_LOG.md，也不要发给我和 WorkBuddy。
- 删文件、重装、改系统设置这类操作，先问你，得到你同意再做。
